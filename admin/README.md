# راه‌اندازی پنل Decap CMS

این پنل محتوای مخزن `x-iran-x/ryukmanga-media` را ویرایش می‌کند. **تا وقتی OAuth تنظیم نشده، پنل آماده ورود نیست.**

## پیش‌نیاز امنیتی
Decap با backend گیت‌هاب به یک OAuth service نیاز دارد. مقدار `backend.base_url` در `config.yml` عمداً placeholder است؛ آن را با آدرس واقعی سرویس OAuth جایگزین کنید. هرگز GitHub Personal Access Token یا `client_secret` را داخل `config.yml`، کد سمت کاربر یا مخزن عمومی قرار ندهید.

## راه‌اندازی OAuth
1. یک GitHub OAuth App بسازید که دسترسی‌اش فقط به مخزن محتوای لازم محدود باشد، تا حدی که راهکار OAuth انتخابی اجازه می‌دهد.
2. سرویس OAuth سازگار با Decap CMS را روی یک سرویس امن سمت سرور مستقر کنید؛ Client Secret باید فقط در متغیر محیطی محرمانه همان سرویس باشد.
3. آدرس سرویس را در `backend.base_url` قرار دهید و مسیر `auth_endpoint` را با سرویس هماهنگ کنید.
4. در تنظیمات GitHub OAuth App، callback URL دقیق سرویس را ثبت کنید.
5. قبل از استفاده واقعی، ورود و خروج، ایجاد/ویرایش/حذف یک پست آزمایشی، بارگذاری فایل، نمایش مسیر فایل و برگشت نسخه از Git را آزمایش کنید.

## نکته‌های مهم
- تنظیمات فعلی هنوز به‌صورت کامل با schema و رفتار واقعی سایت end-to-end آزمایش نشده‌اند.
- مجموعه‌ها به صورت فایل‌های JSON در `_data/<collection>` تنظیم شده‌اند؛ باید مطمئن شوید قالب `catalog.json` و صفحات سایت همین ساختار و فیلدها را می‌خوانند.
- حذف یک آیتم در پنل، فایل JSON آن را از مخزن حذف می‌کند؛ فایل‌های رسانه‌ای قدیمی ممکن است جداگانه باقی بمانند و باید بررسی شوند.
- تغییرات این شاخه هنوز در `main` ادغام یا روی Vercel منتشر نشده‌اند.
